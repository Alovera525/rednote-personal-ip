# 文案交付与排版规范

这份规范解决三件事：按账号阶段建立本篇方向、让正文在手机上好读而非碎成一句一段、默认直接交付可发布文案。

## 1. 初次完整创作：按账号阶段分流

用户要“标题 + 正文”或“完整笔记”时，先问“这是从零起号，还是已有在运营的账号？”。默认直接在聊天中输出可发布文案；用户明确说“给我 .md / txt”时才切换格式。

- **从零起号**：在知道行业 / 身份和目标读者后，展示 3 个「个人 IP 风格 + 文章口气」组合，标出推荐项；用户选一个或确认推荐，再确认本篇表达方式。用户可补充 1–3 个参考账号的链接、截图或代表笔记，并说明想参考什么；只借鉴定位、选题支柱、栏目、结构与信息密度，不能照搬原文、独特口头禅、个人经历或具体封面设计。
- **已有账号**：请用户粘贴 1–3 篇自己的或已获授权的爆帖。先提取风格、口气和微习惯，再让用户确认；禁止复制原文或用他人内容建立档案。
- **已有已确认档案**：只回显本篇表达方式和两个风格落点；用户可快速确认或修改。

未完成对应卡片确认前，不生成完整标题和正文。

```text
【新号创作卡 / 账号风格确认卡】
- 个人 IP 风格：<新号用户选定 / 爆帖提炼后确认 / 沿用>
- 文章口气：<用户选定 / 爆帖提炼后确认 / 沿用>
- 参考方向：<可空；只写可借鉴的定位 / 栏目 / 结构>
- 本篇表达方式：<干货 / 故事 / 观点 / 复盘 / 测评 / 文化评论>
- 风格落点：<本篇会执行的 2 个具体动作>

确认后开始；也可只改其中一项。
```

- **个人 IP 风格**：长期“谁在说话”；新号由用户选择或确认推荐，成熟账号由本人爆帖提炼后确认。
- **文章口气**：这一阶段与读者说话的气质，例如冷静拆解、真诚陪伴、犀利直说、轻松口述或克制审美；不同于“干货 / 故事”等内容结构。
- **参考方向**：其他账号只能作为定位与内容方法的参考，不作为可复制的声音模板；必须转换为用户自己的风格与内容锚点。
- **本篇表达方式**：本条“怎么组织内容”，只能选一个主模式：A 干货拆解、B 真实故事、C 观点表达、D 复盘日记、E 清单 / 测评、F 文化评论（影评 / 书评 / 艺术与社会观察）。
- **风格落点**：本篇必须实际出现的两个可观察动作，而不是只显示风格名称。例如“先拆误区再说边界”“用一个真实场景收尾”。
- **默认交付**：标题、正文、hashtags 和置顶评论直接在聊天中输出，方便复制发布；不额外标注文案格式。

用户明确说“你帮我选”可接受风格推荐，但新号仍须确认推荐的 IP 风格与文章口气；已有账号仍须先确认爆帖提炼结果。完整的主 / 辅助 / 不要风格选择、样稿校准和长期档案，留给 `/xhs-voice` 或用户主动要求看风格选项时；不要把快速创作变成建档问卷。

## 2. 正文段落规则

不要为了模拟手机屏幕而每句话换行，也不要用固定句数切段。**一段是一个完整的逻辑单元**：一个观点、一段场景、一个证据、一组连续动作，或一个结论及其解释。

- 只有出现新观点、新场景、新证据、新行动阶段或明确转折时才分段；同一意思还没说完就继续写在同一段。
- 钩子、引用、真正的转折或结尾 CTA 可以单句成段；不是为了制造“金句感”。
- 小标题用于标出逻辑层级；emoji / 颜文字不是每段的项目符号。
- **最终交付必须真的保留换行：** 每两个逻辑段之间使用两个换行符（`\n\n`），让用户复制到小红书后看到**恰好一行空白**。不能只换一行让段落挤在一起，也不能使用三个或更多换行符制造连续两行空白。
- 不插入只为了“看起来短”的空行；同一逻辑段内不换行。
- 列表、步骤和轮播页文案可更短，但每项仍须完整表达一个动作、证据或判断。

```text
这是第一段：完整讲同一个场景、观点或连续动作。

这是第二段：进入新的证据、行动阶段、转折或结论。
```

## 3. 逻辑主线

完整笔记在正文前先确定一个**核心结论 / 想让读者带走的东西**，再按本篇表达方式组织逻辑链：

- 干货拆解：结论 → 原因 → 方法 → 适用边界
- 真实故事：场景 → 变化 / 冲突 → 选择 → 领悟或余味 → 可选轻行动
- 观点表达：判断 → 论据 → 反例或边界 → 行动
- 复盘日记：目标 → 过程 → 卡点 → 调整 → 下一步
- 清单 / 测评：条件 → 过程 → 优缺点 → 适合谁 / 不适合谁
- 文化评论：观看 / 阅读触发 → 可核对线索 → 自己的理解 → 意象或余味

故事可以升华，但领悟必须从前文的具体场景、变化或选择自然长出来；若故事本身已成立，停在余味即可，不强行写成通用人生道理。

### 实质内容检查

核心结论不能只靠情绪判断或泛泛鼓励支撑。完整笔记至少要有两个内容锚点，其中至少一个是可核对的事实、过程、方法、判断标准、对比维度或适用边界。每一段必须提供原因、步骤、证据、取舍或边界之一；只有抽象金句或情绪判断的一段，必须补材料或删除。

## 4. emoji / 颜文字

这里的“表情”默认指 Unicode emoji 或颜文字，不是图片贴纸。图片贴纸与封面继续属于视觉分支。

- 没有用户偏好时，完整正文最多 1–3 个；只放在情绪转折、轻提示或 CTA，不能每段都放。
- 有明确档案时只从用户确认的 emoji / 颜文字池中选；一篇只用 1–2 种。
- 专业、医疗、法律、财务内容默认不用，除非用户明确要求且不影响严谨性。
- 用户说“不用 emoji”是硬禁用，不以“更像小红书”为由添加。

## 5. 聊天交付

文案完成并通过第 5 步自检后，默认直接在聊天中给出最终版本：标题、正文、显式三层 hashtags、置顶评论和内容成长诊断，方便复制发布；不生成附件。只要标题、只改一句、短改写等轻量任务不附内容成长诊断。

完整笔记中的标签必须让用户看到层级，不能只把 hashtag 混成一行：

```text
【Hashtags】
- 大词（2–3）：#… #…
- 精准词（3–4）：#… #…
- 个人 IP / 栏目词（1–2）：#… #…
```

没有已确认账号名时，个人 IP 层使用可持续经营的栏目词，例如 `#Vera的品牌手记`；不能临时虚构账号名、粉丝称呼或不属于用户的身份。标签总数保持 3–10 个，且计入正文字数。

内容成长诊断的具体评分和输出格式见 `references/content-diagnosis.md`。它只评价当前确认材料和当前稿的可发布程度，不预测流量，也不把“风格不明显”解读为用户本人没有个性。

| 用户明确要求 | 交付内容 |
|---|---|
| Markdown（`.md`） | 同一内容，以 `# 标题`、`## 正文`、`## Hashtags`、`## 置顶评论`、`## 内容成长诊断` 组织，可保存为 `.md` |
| 纯文本（`.txt`） | 同一内容的纯文本；无 Markdown 标记，可保存为 `.txt` |

用户没有明确要求 `.md` 或 `.txt` 时，不额外询问格式。需要文件时，用户自行保存聊天内容；本插件保持纯 Markdown，不附带程序或导出器。
