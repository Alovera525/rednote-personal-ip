# 文案交付与排版规范

这份规范解决三件事：用快速创作卡确定本篇方向、让正文在手机上好读而非碎成一句一段、在对话中按用户需要交付可复制的格式。

## 1. 快速创作卡（默认）

用户要“标题 + 正文”或“完整笔记”时，写完整草稿前只展示一张快速创作卡。它不是问卷：用户只需回复“按推荐写”，或改其中一项。没有这一步确认，不生成完整标题和正文。

```text
【快速创作卡】
- IP 风格：A10 成长日记员（沿用 / 暂定）
- 本篇表达方式：D 复盘日记
- 风格落点：保留一个真实卡点；用第一人称写清一次调整
- 交付格式：Word 友好版（沿用 / 首次默认）

回复“按推荐写”即可开始；也可只改其中一项。
```

- **IP 风格**：长期“谁在说话”；有档案时沿用，没有时按行业暂定一个推荐。
- **本篇表达方式**：本条“怎么组织内容”，只能选一个主模式：A 干货拆解、B 真实故事、C 观点表达、D 复盘日记、E 清单 / 测评。
- **风格落点**：本篇必须实际出现的两个可观察动作，而不是只显示风格名称。例如“先拆误区再说边界”“用一个真实场景收尾”。
- **交付格式**：Word 友好版、Markdown（`.md`）或纯文本（`.txt`）。首次默认 Word 友好版；用户改过后作为后续默认，不在每篇重复追问。这是聊天中的交付格式选择，不创建或下载任何文件。

用户明确说“你帮我选 / 快速开始”时，快速创作卡回显后即可继续。完整的主 / 辅助 / 不要风格选择、样稿校准和长期档案，留给 `/xhs-voice` 或用户主动要求看风格选项时；不要把快速创作变成建档问卷。

## 2. 正文段落规则

不要为了模拟手机屏幕而每句话换行，也不要用固定句数切段。**一段是一个完整的逻辑单元**：一个观点、一段场景、一个证据、一组连续动作，或一个结论及其解释。

- 只有出现新观点、新场景、新证据、新行动阶段或明确转折时才分段；同一意思还没说完就继续写在同一段。
- 钩子、引用、真正的转折或结尾 CTA 可以单句成段；不是为了制造“金句感”。
- 小标题用于标出逻辑层级；emoji / 颜文字不是每段的项目符号。
- 段落之间空一行；不插入只为了“看起来短”的空行。
- 列表、步骤和轮播页文案可更短，但每项仍须完整表达一个动作、证据或判断。

## 3. 逻辑主线

完整笔记在正文前先确定一个**核心结论 / 想让读者带走的东西**，再按本篇表达方式组织逻辑链：

- 干货拆解：结论 → 原因 → 方法 → 适用边界
- 真实故事：场景 → 变化 / 冲突 → 选择 → 领悟或余味 → 可选轻行动
- 观点表达：判断 → 论据 → 反例或边界 → 行动
- 复盘日记：目标 → 过程 → 卡点 → 调整 → 下一步
- 清单 / 测评：条件 → 过程 → 优缺点 → 适合谁 / 不适合谁

故事可以升华，但领悟必须从前文的具体场景、变化或选择自然长出来；若故事本身已成立，停在余味即可，不强行写成通用人生道理。

## 4. emoji / 颜文字

这里的“表情”默认指 Unicode emoji 或颜文字，不是图片贴纸。图片贴纸与封面继续属于视觉分支。

- 没有用户偏好时，完整正文最多 1–3 个；只放在情绪转折、轻提示或 CTA，不能每段都放。
- 有明确档案时只从用户确认的 emoji / 颜文字池中选；一篇只用 1–2 种。
- 专业、医疗、法律、财务内容默认不用，除非用户明确要求且不影响严谨性。
- 用户说“不用 emoji”是硬禁用，不以“更像小红书”为由添加。

## 5. 聊天交付格式

文案完成并通过第 5 步自检后，按用户选定的格式在聊天中给出最终版本。不得因切换格式重新改写、补充事实或改变已确认的声音。

| 选择 | 交付内容 |
|---|---|
| Word 友好版 | 标题、正文、hashtags、置顶评论；无 Markdown 标记、自然段清晰，可直接复制到 Word |
| Markdown（`.md`） | 同一内容，以 `# 标题`、`## 正文`、`## Hashtags`、`## 置顶评论` 组织，可保存为 `.md` |
| 纯文本（`.txt`） | 同一内容的纯文本；无 Markdown 标记，可保存为 `.txt` |

Word 友好版不是 `.docx` 附件。需要文件时，用户自行将交付内容粘贴进 Word，或保存为所选的 `.md` / `.txt`；本插件保持纯 Markdown，不附带程序或导出器。
