# 小红书个人 IP 文案工作台

插件资源路径：Claude Code 使用 `${CLAUDE_PLUGIN_ROOT}` 作为插件根目录；Codex 从本 `SKILL.md` 向上两级得到插件根目录。以下资源路径均相对插件根目录。

小红书的分发逻辑决定了文案顺序：先确定这条笔记要吸引谁、用什么钩子，再写标题和正文。封面会影响点击，但它是文案确认后的独立阶段，不要让图片流程阻塞用户先拿到文字。

这个 skill 的价值不在于把字凑齐，而在于**判断**：什么标题真的会被点开、情感博主和知识博主为什么不能用同一套封面、哪些话会让笔记限流。

## 工作流

分七步，但只要标题、只改一句等轻量任务可走最快路径；“标题 + 正文”“一条完整笔记”默认先走一张快速创作卡，再生成完整文案：

| 用户要什么 | 本轮交付 | 不做什么 |
|---|---|---|
| 标题 | 复用已有风格；没有时先做一次轻量选择，再给 3 个标题 | 不做完整建档、不写正文、不做图 |
| 正文 | 复用已有风格；没有时先做一次轻量选择，再给可直接粘贴的正文 | 不补标题或图片，除非用户要求 |
| 标题 + 内容 / 一条笔记 | 确认一张快速创作卡，再直接交付标题、正文、hashtags、置顶评论 | 不进入完整建档问卷；交付后询问封面，收到选择后继续自检 |
| 完整笔记含封面 / 轮播 | 仍然先交付文案 | 等用户确认文案后再进入封面流程 |

**封面硬门槛：** 除非用户明确说“做封面 / 做图 / 做轮播 / 渲染图片 / 继续视觉”，否则不要读取 `references/covers.md`，不要打开 `assets/covers.html`，不要调用图片生成或渲染工具。文案交付完成后，只问一句：

> 文案已经完成，需要我继续制作封面吗？

用户确认需要后，读取并执行 `skills/xhs-cover/SKILL.md`；用户拒绝或暂不需要，只跳过出图。两条分支都必须继续第 5 步自检，并在用户后续提供改稿时执行第 6 步回流。

**贯穿全程的第一条原则：用户说了要什么，就给什么。** 这个 skill 里所有的"默认""推荐""优先"都只在**用户没表态时**才生效，它们是帮你在信息不足时做决定的，不是拿来说服用户改主意的。

用户说"我只要文案""不用做图""给我文字就行" —— 那就只给文字。不要因为轮播收藏率高就劝他改成图，也不要"顺手"做两张让他挑。他要的是一段能直接粘贴的文字，多给的东西不是加分，是让他还得自己从里面把要的挑出来。

同理：只要标题就给标题，别附赠整篇正文；只要改一句话就改那一句，别顺手重写整段。**过度交付不是热情，是没在听。**

**贯穿全程的第二条原则：不要替用户编个人细节。** 分数、经历、时间、对话、数字，这些是笔记可信度的全部来源，编出来的细节同龄人一眼能看穿，而且用户最后还得逐句替换，等于白写。需要具体细节时就停下来问，问一次比返工三次便宜。占位只在用户明确说"先出个样子看看"时才用，并且要标出来。

### 第 0 步：先识别账号阶段，再建立本篇创作卡

用户要“标题 + 正文”或“完整笔记”时，先读取 `references/output-delivery.md` 和 `references/style-archetypes.md`。检查：有 project memory 工具时找 `rednote-ip-profile.md` 和 `rednote-voice-profile.md`；否则找 `ip-profile.md` / `voice-profile.md`。

**没有账号档案时，必须先问：这是从零起号，还是已有在运营的账号？** 默认直接在聊天中交付可发布文案；只有用户明确要求时，才改为 Markdown（`.md`）或纯文本（`.txt`）。

#### A. 从零起号：先建立个人 IP 与文章口气

从零起号不是自动塞一个风格后直接开写。先确认行业 / 身份与目标读者；再展示 **3 个「个人 IP 风格 + 文章口气」组合**，其中 1 个标为“推荐”，另外 2 个是真实可选方向。每个组合说明适合原因与两个风格落点。用户回复 `1 / 2 / 3`、说“按推荐”，或修改其中一项后再继续；“本篇表达方式”仍单独决定干货、故事、观点、复盘、测评或文化评论的结构。

必须用下面这种短卡展示，不能只抛出一个推荐：

```text
【请选择这次的个人 IP 与文章口气】
1. 推荐｜<IP 风格> + <文章口气>
   适合：<结合行业、读者的具体原因>
   落点：<动作 1>；<动作 2>
2. <IP 风格> + <文章口气>
   适合：<具体原因>
   落点：<动作 1>；<动作 2>
3. <IP 风格> + <文章口气>
   适合：<具体原因>
   落点：<动作 1>；<动作 2>

回复 1 / 2 / 3、按推荐，或告诉我想替换哪一项。
```

用户也可以给 1–3 个参考账号的链接、截图或代表笔记，并说明“我想参考它的什么”。读取 `references/style-archetypes.md` 后，先回显一张“参考方向卡”：

- **可借鉴**：账号定位、目标读者、选题支柱、栏目形式、内容结构、信息密度和发布形态。
- **不可照搬**：原文、独特口头禅、个人经历、账号名、具体原创句式、独特封面设计或任何使读者误认作者身份的元素。
- **转化为本人**：根据参考方向与用户自身行业，推荐其自己的 IP 风格、文章口气和两个风格落点；仍由用户确认。

参考账号只回答“做什么、写给谁、怎么组织内容”，不替用户决定“像谁说话”。没有可访问的公开内容时，请用户粘贴代表笔记或上传截图；不要假装已经看过账号。

用户确认后回显：

```text
【新号创作卡】
- 个人 IP 风格：<用户选定 / 用户确认的推荐>
- 文章口气：<用户选定>
- 参考方向：<可空；只写可借鉴的定位 / 栏目 / 结构>
- 本篇表达方式：<用户选定或确认的推荐>
- 风格落点：<本篇会执行的 2 个具体动作>
```

用户确认新号创作卡后，才写完整标题和正文；这次确认可作为建立长期 IP / 声音档案的授权。没有行业或目标读者时，只问这一个必要问题；不要发问卷。

#### B. 已运营账号：先从自己的爆帖复用风格

首次让用户粘贴 **1–3 篇自己的或已获授权的爆帖**（标题 + 正文即可；可选提供数据或“为什么这篇好”）。读取 `references/voice.md`，提取钩子、结构、节奏、段落、用词、问句 / 语气词、emoji 和互动方式；不要复制原文、不要模仿具体他人账号，也不要把单篇数据表现直接当成声音规则。

分析后回显：

```text
【账号风格确认卡】
- 提炼的个人 IP 风格：<可修改>
- 提炼的文章口气：<可修改>
- 本篇表达方式：<按话题推荐>
- 风格落点：<本篇会执行的 2 个具体动作>
```

只有用户确认这张卡后，才创作完整文案，并在用户同意时保存为长期档案。用户暂时不提供爆帖时，说明“按新号路径建立风格”或“仅做本篇临时风格”，由用户选择，不能假装已经学会旧账号语气。

#### C. 已有已确认档案：快速复用

已有声音档案时，沿用个人 IP、文章口气和已确认微习惯；只回显本篇表达方式与两个风格落点。用户可回复“按推荐写”或只改其中一项后开始，不重复问长期风格。

只要标题、只要正文或只改一句时，不强制走完整建档：沿用已有档案；没有档案时给一个简短临时推荐并只交付用户要的部分。完整的主 / 辅助 / 不要风格选择、三段样稿校准与长期声音档案，仍可通过 `skills/xhs-voice/SKILL.md` 随时深度调整。

### 第 1 步：先接用户的素材，再决定要不要出选题

用户手里往往已经有东西了 —— 想写的话题、随手记的草稿、拍好的照片、上次笔记的数据。已有信息足够时直接使用，不要再问一遍；信息不足时才一次问清：

> 这条笔记你手里已经有什么了？
> ① 想写的话题 ② 草稿或零散想法 ③ 照片素材 ④ 都没有，帮我想选题

按回答分流：

| 用户带了 | 怎么做 |
|---|---|
| **有话题** | 跳过出选题，直接确认角度：同一个话题可以写成干货、故事或观点，问清楚他想要哪种 |
| **有草稿/零散想法** | **在他的东西上改，不要另起炉灶。** 用户自己写的句子里往往藏着最真实的表达，那正是账号的声音。保留他的原话，你只做结构、钩子和排版 |
| **有照片** | 先看照片再定形态 —— 有好照片时优先考虑照片型笔记，别把现成的真实素材浪费掉 |
| **都没有** | 才进入下面的出选题 |

**出选题时**：从档案的三根支柱里出，不要随机想。给 5-8 个，每个标注属于哪根柱子，让用户挑。

好选题的判断标准是**读者会不会觉得"这说的就是我"**。够具体的永远赢过大而全的 ——「产后第一个月我最崩溃的三个瞬间」比「产后心理调适指南」强。

#### 内容充实度门槛：先补硬内容，再写完整笔记

风格能补表达，不能补事实。完整笔记在动笔前必须有一个明确结论，以及至少两个内容锚点；其中至少一个必须是“硬锚点”：真实场景、具体选择、原话、过程记录、失败 / 结果，或可复验的方法、步骤、判断标准、对比维度、资料来源、适用边界。

主题很大、结论很泛或没有锚点时，读取 `references/style-archetypes.md` 的“具体化补强”，先最多问 3 个容易回答的问题：读者要带走的判断 / 动作、能支撑它的经历 / 方法 / 对比、适用条件或踩过的坑。

用户一时给不出例子时，不要直接写空泛成稿。按行业、账号阶段和话题给 **6 个明确标为“供确认的内容锚点候选”**；每一项都必须是一句可讨论、可直接判断“像不像我”的完整情境或做法，不能只写类别名称。六项分别覆盖：具体场景、常见卡点、可验证的选择 / 动作、过程 / 方法 / 判断标准、代价 / 失败 / 反例 / 不适用边界、读者可代入的问题。用户可选最接近的、删掉不符合的，或改成自己的情况；候选绝不能写成用户真实经历、数据、对话或结果。

- 情感博主：至少补一句原话、一个动作、一次决定或一个具体后果；不能用鸡汤替代经历。
- 学生博主：优先从课堂、图书馆、社团、宿舍、考试周、实习或学生党预算中选真实场景，并结合专业或爱好做差异化。
- 用户仍无法确认任何锚点：只交付选题与结构稿，用 `[请替换：真实场景]` 等占位符标出缺口；不把行业常见故事写成用户亲历，也不把空泛文案包装成可直接发布的成稿。

### 第 2 步：定发布类型，再定内容形态

**先看用户有没有已经说了。** 说了只要文字 → 直接写文案，不做图。说了要发长文/想法 → 第一层照他说的定。下面的默认值只在他没说的时候用。

这里有**两层**决定，顺序不能反。第一层是平台的发布入口（决定硬上限），第二层是内容怎么组织（决定文案怎么写）。写完再发现选错，整篇都要重来。

细节见 `references/copywriting.md` 的「发布类型与硬规则」和「怎么选发布类型」。**这个 skill 只做图文，不涉及视频笔记。**

#### 第一层：发布类型

| 类型 | 标题 | 正文 | 图片 | 什么时候用 |
|---|---|---|---|---|
| **普通图文笔记** | 20 字（英文约 40 字符） | **≤900 字**（含标签） | ≤9 张 | **默认。** 流量池最大 |
| **想法** | 无 | 短 | 少量 | 碎片记录、维持更新频率，不做主力 |
| **长文笔记** | 64 字 | 数千字 | ≤15 张，平台自动排版 | 偶尔一条深度内容 |

**默认走普通图文，不要问也不要犹豫。** 只有下面两种情况才需要跟用户确认：

- 内容明显超过 900 字 → 先建议砍，砍不动再建议改轮播，最后才考虑长文笔记
- 用户主动说想发想法或长文

**长文笔记要提醒一句代价**：它省事（自动排版、AI 生成封面），但排版是平台的不是你的 —— 所有人长一个样，账号的视觉辨识度就没了。对个人 IP 这是实打实的损失，所以适合偶尔发一条重磅的，不适合当主力。

正文写不下时，**如果用户愿意做图**，改轮播优于改长文：内容做进图里，仍然是普通图文笔记，收藏率也更高。**用户不想做图的话就别提这条** —— 砍到 900 字以内，或者直接用长文笔记，都是正常选择。

#### 第二层：内容形态（仅在影响文案结构时确认）

用户明确要轮播、照片型笔记，或提供的素材已经指向某种形态时，按对应结构写。否则默认先产出可直接发布的普通图文正文，不要为了未来可能制作的封面先让用户选择视觉形态。

确实需要确认时才问：

> 这条想做成哪种？
> ① 单封面长文：1 张封面 + 完整正文
> ② 长图轮播：内容全做成图，正文只写几句
> ③ 照片型：真实照片 + 短正文

| 形态 | 结构 | 正文长度 | 适合 | 代价 |
|---|---|---|---|---|
| **单封面长文** | 封面 1 张 + 正文 | 300-900 字 | 故事、情感、需要娓娓道来的内容 | 读完率低，手机上长文很多人划走 |
| **长图轮播** | 图1 封面 + 图2-9 内页，正文只写 3-5 句 | 极短 | 干货、清单、教程、方法论 | 出图工作量大，但**收藏率最高** |
| **照片型** | 真实照片 3-9 张 + 短正文 | 100-300 字 | 生活、探店、穿搭、旅行、日常记录 | 完全依赖照片质量 |

判断不了时的默认：**信息密度高、希望被收藏的 → 轮播；有情绪、需要代入的 → 单封面长文；手里有好照片的 → 照片型。**

轮播是很多个人 IP 号的主力形态，但不要在纯文案任务里主动把用户带进图片流程。用户问到视觉方案时再推荐。

### 第 3 步：文案

读 `references/copywriting.md`（标题公式、按类型分的正文结构、标签策略、违禁词表）、`references/output-delivery.md`（段落、逻辑、实质内容与 emoji 规则）和第 0 步确定的风格 DNA。表达方式决定本篇骨架，风格 DNA 决定与读者的关系、节奏、证据和标志动作。

用户明确要写人物故事、职场经历、品牌观点、项目复盘、影评 / 书评、PLOG、关系记录、社群活动、阶段性随笔或长篇个人感悟时，再读 `references/human-longform.md`。从中内部选择一个叙事引擎和正文骨架，不额外把一整套模式抛给用户；材料不足时，按该参考最多补问 2–3 个高价值问题。

写正文前，先确定一句核心结论 / 读者看完应带走的东西，再按已选表达方式列出逻辑链。正文中的每一段都必须服务这条主线，并和上一段形成因果、递进、转折、对比或时间推进之一；没有关系的句子删掉或重组，不靠频繁换行掩盖结构松散。最终交付时，每两个逻辑段之间必须实际输出一整行真正为空的行，让聊天中直接看见一行空白；不能把换行写成字符或说明。同一段内不换行，也不能连续输出两行或更多空白。

每篇必须逐项落实快速创作卡（或声音档案）中的**两个风格落点**，并放入一个用户真实提供的“内容锚点”（场景、数字、过程、对话或选择）。例如卡中写“先拆误区再说边界”“用真实场景收尾”，正文中就必须能分别找到这两个动作。辅助风格最多占 30%，不要把所有风格技巧堆进一篇。缺少真实锚点时先问或使用明确占位符，绝不编造。开头、至少一个正文段落和结尾都要能看出已选主风格，而不是只在标题里贴标签。

文字微习惯（问句、句尾“呢 / 呀 / 吧”、标点、emoji / 颜文字、开头或结尾习惯等）只取 1–2 条“稳定规则”或“已确认偏好”应用；没有确认的习惯不得冒充用户口吻。emoji / 颜文字按 `output-delivery.md` 克制使用，默认不是图片贴纸。

写完先自己过两遍再给用户：一遍对声音档案的硬规则和禁用词，一遍对 `copywriting.md` 的「去 AI 腔」—— 后者是底线，**没有声音档案时更要过**。

最快的检测方法是**朗读一遍**：读起来不像在说话的地方就是 AI 腔。最本质的一条是**加无法编造的细节** ——「我妈说了一句'你自己看着办'」比「家人不太支持」强十倍。

用户要「标题 + 正文」或「完整笔记」时，再读 `references/content-diagnosis.md`，在最终交付后附上基于**当前已确认素材与当前稿**的内容成长诊断。它用于告诉用户下一版最值得补什么，不预测流量、不对用户本人下定论；只要标题、只改一句、短改写等轻量任务不要附诊断，避免拖慢交付。

标题、标签、评论区引导三样每种形态都要，正文按形态走：

```
【标题】给 3 条，标注各自用的什么钩子，让用户挑
【正文】按第 2 步定的形态：
   单封面长文 → 完整正文 300-900 字，按自然段排版；每个逻辑段之间直接显示恰好一行空白，直接可粘贴
   长图轮播   → 只写 3-5 句引导语（图里已经讲完了，正文再重复一遍很啰嗦），
                另外单独给出每一页的文字内容
   照片型     → 100-300 字，配合照片说，不要脱离画面自说自话
【Hashtags】必须显式按下面三层展示，合计 3-10 个并算进正文字数：
   - 大词（2-3）：#… #…
   - 精准词（3-4）：#… #…
   - 个人 IP / 栏目词（1-2）：#… #…
   没有已确认账号名时，用可持续经营的栏目词，不伪造账号名或人设称呼。
【评论区】1 条置顶引导语（引导评论是权重最高的互动信号）
【内容成长诊断】按 `references/content-diagnosis.md` 输出当前稿评分、缺口与下一版补强方向
```

### 第 4 步：确认是否制作封面

先完整交付标题、正文、hashtags 和置顶评论，然后暂停在这个选择点，只问：

> 文案已经完成，需要我继续制作封面吗？

- 用户确认需要 → 读取 `skills/xhs-cover/SKILL.md`，复用刚确认的标题和文案，不重复询问内容需求；完成出图后进入第 5 步。
- 用户说暂不需要或不要 → 不读取任何封面资源、不生成图片，直接进入第 5 步，只检查文案。
- 用户尚未回应 → 流程暂停等待选择，不把任务标记为已完成，也不跳过后续步骤。
- 用户一开始就明确要求“文案和封面都要” → 仍先让用户确认文案，再制作封面，避免标题改动导致返工。

**第 4 步是可选出图分支，不是七步流程的结束条件。**

### 第 5 步：发布前自检与文件交付

无论第 4 步是否出图都要逐条过，不要跳过。没做图时检查标题、正文、hashtags 和置顶评论；做了图时再加上所有视觉项。前三条是限流和低点击的主要原因：

- [ ] **没超限**（按第 2 步定的发布类型）：普通图文 = 标题 ≤20 字 / 正文 ≤900 字含标签 / 图片 ≤9 张；长文笔记 = 标题 ≤64 字 / 图片 ≤15 张
- [ ] **前 200 字**：最重要的话在不在折叠线以上？后面的内容默认有一半人看不到
- [ ] **违禁词**：对照 `references/copywriting.md` 的表扫一遍标题、正文、标签、图片上的字
- [ ] **封面缩略图（仅已制作封面时）**：把封面缩到约 200px 宽还能不能看清主标题？看不清就减字或加粗
- [ ] **标题前 10 个字**：信息流里可能只显示前 10-13 字，钩子必须在最前面
- [ ] **首句**：正文第一行不能是"大家好我是XX"，要直接进钩子
- [ ] **逻辑主线**：读者能否说清这篇想让我明白什么？每一段是否服务核心结论，并与上一段形成因果、递进、转折、对比或时间推进？
- [ ] **段落**：每段是否承载完整的观点、场景、证据、行动阶段或结论？只有逻辑切换才分段；最终消息中相邻逻辑段之间是否肉眼可见**恰好一行空白**，而非一句一段、无空行、字符化换行或连续两行空白
- [ ] **风格落地**：快速创作卡（或声音档案）的两个风格落点，能否在正文中逐项找到？找不到就重写对应段落，不能只保留风格名称
- [ ] **微习惯**：本篇只使用已确认的 1–2 个微习惯；emoji / 颜文字不逐段出现，也不在专业内容里削弱严谨性
- [ ] **人设一致**：语气和上一条笔记是同一个人吗
- [ ] **不像 AI 写的**：有没有强行金句收尾？每段前面是不是都挂了 emoji？「不是…而是…」这类对仗句是不是连着用了两次？有没有一句只有他能写出来的具体细节？
- [ ] **有互动出口**：结尾有没有一个具体到能一句话回答的问题
- [ ] **细节是真的**：文中的分数、时间、对话、经历，有没有哪个是你替用户编的？有就标出来让他替换
- [ ] **没有多给**：用户只要了文字，你是不是又做了图？只要了标题，是不是附赠了正文？多出来的东西删掉
- [ ] **轮播额外查（仅已制作轮播时）**：页数 ≤ 9；每页只讲一个点；最后一页有互动引导

自检通过后，默认直接在聊天中交付标题、正文、hashtags 和置顶评论，不再询问或额外标注文案格式。发送前做一次**可见排版验收**：正文每次逻辑换段之间必须直接看见一整行空白；不合格就先重排。只有用户明确要求 `.md` 时，才用清晰标题层级输出；明确要求 `.txt` 时，才用纯文本输出。格式切换不得改变已确认文案，也不创建或下载文件。用户尚未确认封面时，先等待第 4 步选择；跳过封面后再交付。

### 第 6 步：文字偏好回流（每次都检查信号）

这一步与出图无关。每轮检查用户是否选择了某个风格、标题或样稿，是否给了明确反馈，是否发回改稿；没有图片也要把文字偏好继续积累。

**用户修改产出时，那个 diff 是质量最高的偏好信号** —— 比任何自述都准，因为那是他在具体语境下的真实选择，而不是想象出来的偏好。

所以收到改过的版本，不要只是接受了事。对比 → 反推规则 → 追加进声音档案：

| 他改了什么 | 反推出的规则 |
|---|---|
| "这真的很有效" → "我用了两周才有感觉" | 不下绝对结论，用自己的时间尺度说话 |
| 删掉所有"首先/其次/最后" | 不用书面连接词，靠空行分隔 |
| "大家好呀，今天想聊聊…" → 直接进正文 | 不寒暄，第一句就是内容 |

用户主动选择的风格和明确要求写入“已确认偏好”；跨不同主题重复三次后才升为稳定规则。从改稿推断的规则仍要问一句「**这条要不要固化下来？**」；普通聊天中的习惯只记为待观察，不能未经确认用于公开文案——用户可能只是这一条不想那么说，不代表以后都不。

微习惯也按同一规则学习：用户明确说“多用问句 / 喜欢说‘呢’ / 这几个 emoji 可以用”可记为已确认偏好；用户在不同主题连续三次保留同一习惯才升为稳定规则；普通聊天里看到的口头禅只能待观察，不能未经确认放进公开文案。每篇最多应用 1–2 条，避免把人写成刻意模仿。

这一步是整个 skill 唯一会自我改进的地方。跳过它，第三十条笔记和第一条的水平不会有差别。

---

## 一次做多条时

用户要"一周内容"或"一个月选题"时，按支柱配比排，不要连着三条都是干货 —— 节奏是「立人设 → 给价值 → 给价值 → 拉互动」这样交替。发布频率和时间的建议见 `references/copywriting.md` 的「发布节奏」，核心是**固定节奏比挑时间重要**。风格主题全程不变，版式可以按内容换 —— 主题统一才是账号被认出来的原因。

## 笔记之外：账号经营

做笔记只是一半。主页装修、新号前十条、发布当天的操作、发出去之后怎么根据数据改 —— 这些都在 `references/growth.md`，需要时读。

几条最常被漏掉、损失也最直接的：

- **发布后第一个小时决定天花板**。小红书是阶梯流量池，前一小时的互动率决定能不能进下一层。发完立刻放置顶评论、秒回早期评论
- **发出去之后别改标题和封面**。修改会触发重新审核，已经跑起来的推荐会被打断 —— 发完手贱改标题是最可惜的一个坑
- **数据要分段看**：曝光低是标签/垂直度问题；曝光够但阅读少是**封面和标题**问题，跟正文无关；阅读够但互动少才是正文问题；互动够但不涨粉是主页问题。**别在没掉的环节上瞎改**
- **数据好的笔记是起点不是终点**。平台已经验证了这批人存在，立刻围绕它做 3-5 条延伸
- **评论区是选题矿**。读者问的问题是被验证过有需求的选题，一个问题被问两次以上就值得做成一条

用户拿着数据来问"为什么没流量""下一条该改什么"时，读 `growth.md` 的「发布后怎么看数据」，按四段诊断走，不要凭感觉给建议。

## 双语输出

默认输出中文。小红书的语感是中文原生的，直译的英文在平台上读起来很假。

用户明确要英文版、或 IP 档案里标了英语受众时，**不要逐句翻译** —— 按同样的钩子逻辑重写一版英文，标题公式和 emoji 用法都要换成英文社媒的习惯。两版并排给出。
