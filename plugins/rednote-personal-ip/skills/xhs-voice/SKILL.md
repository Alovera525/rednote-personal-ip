# 小红书声音档案（深度建档）

插件资源路径：Claude Code 使用 `${CLAUDE_PLUGIN_ROOT}` 作为插件根目录；Codex 从本 `SKILL.md` 向上两级得到插件根目录。以下资源路径均相对插件根目录。

读取 `references/voice.md` 和 `references/style-archetypes.md`。这里是深度建档路径：完整选择主 / 辅助 / 不要风格、样稿校准与长期保存都在此完成；普通 `/xhs-post` 默认只用一张快速创作卡。只记录可观察、可执行的特征，不模仿具体博主。

## 交付结构（必须）

不要先用连续长段解释。无论是新建、导入还是更新档案，都按以下四块回显；每项用短条目，用户能一眼确认或改动：

1. **账号定位**：行业 / 身份、目标读者、内容边界。
2. **个人 IP 与文章口气**：主 / 辅助 / 不要风格、与读者关系、两个标志动作。
3. **文字习惯与禁用项**：稳定规则、已确认偏好、待观察、禁用词 / 句式和例句对照。
4. **本次确认与下一步**：本轮新增或调整了什么；用户要确认什么；是否授权保存。只建档时不要顺手写新笔记。

## 新建档案：从零起号

1. 一次问清行业 / 身份、目标读者和明确不喜欢的表达；再明确区分个人 IP 风格（长期是谁）和文章口气（怎么说）。用户说“你帮我选”时可以推荐，但要让用户确认。
2. 根据行业映射只展示 4–6 张风格卡，让用户选 **1 个主风格 + 0–1 个辅助风格 + 1 个明确不要的风格**，并从冷静拆解、真诚陪伴、犀利直说、轻松口述、克制审美等口气中确认偏好。
3. 围绕同一主题生成 3 段 80–120 字的校准样稿，让用户选最像自己的版本；记录选择原因。也可直接先建立暂定档案，不让校准样稿卡住创作。
4. 生成风格 DNA：与读者的关系、情绪温度、叙事视角、证据偏好、最多两个标志动作、禁用词和禁用句式；再建立微习惯栏（问句、句尾语气词、标点、emoji / 颜文字、开头 / 结尾习惯等）。
5. 自然语料改为可选增强项。用户愿意提供时，可用微信长消息、朋友圈、群聊、语音转文字或本人满意的旧笔记继续校准；不要强制要求 3–5 段。
6. 用户同意长期保存后再创建声音档案。IP 定位档案与声音档案分开；没有项目记忆工具时，写入当前工作目录的 `voice-profile.md`。

情感博主与学生博主必须使用对应行业提醒：情感内容要有真实关系节点，不能用空泛鸡汤代替细节；学生内容要从真实校园场景、专业或爱好形成差异，不能虚构学校、成绩、录取或实习经历。

用户从零起号但有参考账号时，可提供 1–3 个链接、截图或代表笔记，并说明想参考的部分。只提炼定位、读者、选题支柱、栏目与结构；不复制原文、口头禅、个人经历、账号身份或独特视觉设计。将提炼结果转化为用户自己的主风格、文章口气和风格落点后，再让用户确认。

## 已运营账号：用爆帖建立档案

1. 请用户粘贴 1–3 篇**自己的或已获授权的**爆帖，至少包含标题与正文；数据、评论和“为什么认为它成功”可选。
2. 分析标题钩子、结构、段落、句长、用词、语气词、问句、emoji / 颜文字、互动方式和明确避免的表达；不要复制原文，不模仿外部具体博主。
3. 把提炼结果回显为“账号风格确认卡”：个人 IP 风格、文章口气、微习惯、两个风格落点和禁用项。用户确认后才保存或用于完整创作。
4. 单篇爆帖只是一条候选信号：数据好可能来自选题或时机，不能直接固化为长期声音规则。

## 更新档案

1. 收集本轮的风格选择、标题 / 样稿选择、明确反馈和改稿差异；没有制作图片也要执行。
2. 用户主动选择或明确说出的偏好，写入“已确认偏好”；跨不同主题重复三次后才升为稳定规则。
3. 从改稿推断的偏好，先问“这条要不要固化下来？”，确认后再写入；普通聊天中的习惯只记入“待观察”，未经确认不得用于公开文案。
4. 把每条偏好改写成可执行规则并给出对应例句；保留适用语境。
5. 新规则与旧规则冲突时保留例外，不要为了统一而抹掉差异。

最终按上述四块交付声音档案和本次新增或调整的规则摘要；不要顺手生成新笔记。用户没有授权保存时，只在对话里展示暂定档案。提醒用户：本篇“干货拆解 / 真实故事 / 观点表达 / 复盘日记 / 清单测评 / 文化评论”是单篇结构选择，不写入长期声音档案。
